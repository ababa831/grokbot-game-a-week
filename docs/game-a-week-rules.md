# Game A Week 運用ルールと設計原則

## コア定義
**ゲーム性 = リスクを冒してリターンを得るかけひき**
どのデメリットを飲んでどのメリットを取るか。すべてのコア動詞に明確なリスクとリターンを対応させる。

---

## ハード制約（絶対厳守）
1. **技術スタック**: Vanilla HTML / JS（Canvas）。外部巨大エンジンや車輪の再発明を避ける。
2. **フックは1つ**: 90%の力を1つの独自メカニクスに注ぐ。余計なシステムを足さない。
3. **Day 5 で機能凍結（カット）**: 5日目で新機能追加を止め、残日は調整・バグ潰し・PR作成・提出準備に充てる。
4. **即リトライ**: 死亡・失敗から1秒以内に操作を返す。長時間の暗転・フェード・待ちは禁止（遅さは罪）。
5. **ヒットストップ必須**: 当たった瞬間に 0.05〜0.1秒 止める。手応えの核。
6. **加算グロー単体禁止**: エフェクトは不透明な芯と黒縁を混ぜる。白飛び・モヤりによる視認性低下を防ぐ。
7. **エンジン/ブラウザ標準フォント禁止**: ゲームのジャンル・世界観に合う無料フォントを初日に当てる。
8. **PR本文の先頭にフック**: GitHub PR の1行目はゲームの核となるフック・動詞を端的に書く。

---

## 1週間の運用サイクル（Day 1 - Day 7）

- **Day 1: コア決定と骨格実装**
  - テーマと核動詞を1つ決め、プランAのみで独裁的に進める（A/B検討・市場調査に時間を使わない）。
  - グレーボックスで最小ループを組む。数値・パラメータはすべて定数/設定ファイルに外出し。
  - 共通フォントと描画スタイル（パレット）を1つ確定。
- **Day 2: 手触り検証と即断ピボット**
  - グレーボックスの段階で動的な反応と面白さがあるか検証。手応えがなければ絵で救おうとせず即ピボット。
  - 重い仕様・合わない要素はこの時点で切り捨てる。
- **Day 3: メカニクス構築とデバッグキー**
  - F1回復/F2スキップ等のデバッグ機能を即座に用意。
  - 15秒のプレゼンを頭で行い、核が濁っていないか確認。
- **Day 4: レベル・ストレス/報酬ループの配置**
  - 単調な坂を作らず、意図的な谷と壁（デコボコ）を手置きする。
  - 敵の種類を増やす代わりに、1種類のサイズ・速度・パラメータを極端に振る。
- **Day 5: 機能カット & テストプレイ**
  - 機能追加を停止。S/Aバグ以外（Cバグ）は放置して線を引く。
  - 黙って他人に触らせる（口頭説明なしで観察し、詰まる箇所を見る）。
- **Day 6: 手触り・演出・サウンドの研磨**
  - 絵よりも音を磨く。ヒットストップ、シェイク、SEの先頭ピークとピッチ揺らぎを調整。
  - 安いノートPCのスピーカーや画面で視認性・聴認性を確認。
- **Day 7: ビルド・PR作成・提出**
  - 3秒で伝わるGIF/スクショを用意。PR本文の先頭にフックを明記して提出。

## 視聴メモに基づく設計原則

### 1. ゲーム性とバランス
- **距離と隙**: 強い行動・高リターンには相応の隙や近接リスクを乗せる。欠点のない全方位攻撃は作らない。
- **ストレス→解消→報酬**: 「ギュッとしてパッと解消」する短いサイクルを作る。
- **デコボコを残す**: 平均化・平坦化は退屈の元。ピーキーな長所と短所を残し、ズルい攻略の穴を残す。
- **救済策**: クリアできないよりマシ。作者基準の難度にせず、易化やスキップを最初から組み込む。

### 2. 企画・画面・UI設計
- **最初の3分・起動即コア**: プロローグや練習部屋（チュートリアル）を作らず、本番のLv1で学ばせる。
- **Mash to Start**: タイトル画面で決定ボタンを連打すれば即ゲームが始まる設計。
- **無反応の排除**: 入力に対してノーリアクションを作らない。成功時は直接称賛し派手に演出する。
- **視認性とコントラスト**: 背景は暗く落として前景・当たり判定を目立たせる。白黒でも読める明暗比。

### 3. モーション・エフェクト・サウンド
- **入力即スナップ**: かまえは0フレーム。攻撃判定の瞬間を最高に見せ、フォロースルーの硬直でバランスを取る。
- **変形と誇張**: ヒット時や着地時のスケール変形（縦潰し・横伸ばし）をコードで入れる。
- **シェイク**: 最大値から減衰（0.9掛けなど）。
- **音の主従**: リザルト・ヒット・死亡音がBGMより明確に大きい。SEは1フレーム目でピークを鳴らし残響を短くする。

### 4. チーム・自己管理・広報
- **開発×広報=成果**: 黙って出さず、動いている核を端的に伝える。
- **完成のために切る**: マスターアップは犠牲の上に立つ。残時間と価値を比較し、不要なこだわりを捨てる。
- **言葉を行動に**: 否定や弱音を行動（コード）に置き換える。
