# ゲーム性・駆け引き・敵AI・バランス設計リファレンス（Gameplay & Mechanics）

YouTube「桜井政博のゲーム作るには」に基づくゲーム性・設計哲学の23原則。
駆け引きの構築、敵AIの設計、難易度調整、リソース管理、コアループの純化時に参照する。

---

### #01 リスクとリターン（駆け引きの本質）
- **核心**: ゲーム性とは「駆け引き」、すなわち「リスクを冒してリターンを得る楽しさ」。プレイヤーの工夫でリスクを抑えてリターンを得るのが「攻略」。安全圏（ノーリスク・ノーリターン）にとどまらせず、リターンのために危険へ飛び込ませる距離・判定・リソースの設計が不可欠。
- **Core Skill**: **トレードオフ状態マシンの構築**
- **AIへの実装・指示原則**:
  - 安全地帯（No Risk / No Return）と危険地帯（High Risk / High Return）を物理座標またはリソース状態で明確に分ける。
  - 「攻撃を当てる」「アイテムを取る」といったリターン獲得行動には、必ず「被弾判定の露出」「隙（硬直時間）」「接近の強制」という代償をバインドさせる。
  - 当たり判定（Hitbox）の寸法そのものをリスクの調整弁として変数化させる。
- **アンチパターン**:
  - 遠距離からリスクなしで敵を一方的に倒し続けられる武器・スキルの放置（ノーリスク・ハイリターン）。
- **チェックリスト**:
  - [ ] プレイヤーが最大リターンを得る瞬間、被弾・失敗リスクが最大化しているか？
  - [ ] プレイヤーがリスクを能動的にコントロールできる「攻略（位置取りやタイミングの工夫）」の余地があるか？

### #02 ギュッとしてパッと解消（緊張と緩和のメカニクス）
- **核心**: 快感は「抑圧（ストレス・溜め）」と「解放（解消）」のギャップから生まれる。風船を膨らませて割るように、エネルギーを溜めさせ、一気に放出させるテンポを作る。
- **Core Skill**: **テンションカーブとチャージサイクルの組み込み**
- **AIへの実装・指示原則**:
  - 行動に「溜め時間（蓄積フェーズ）」を設け、蓄積中は無防備（移動速度低下や回避不可）にすることで一時的なストレスを与える。
  - 解放時にはエフェクト・SE・攻撃範囲を劇的に拡張し、蓄積量に応じた指数関数的なリターン（一掃の爽快感）を返す。
  - カードゲームのコンボ構築やパズルの連鎖準備など、全ジャンルの動詞に「溜めて放つ」周期を定義する。
- **アンチパターン**:
  - 同じ威力の通常攻撃を等間隔で連打し続けるだけのフラットな入力ループ。
- **チェックリスト**:
  - [ ] プレイヤーに意図的な「我慢・制約」を強いるフェーズと、それを一気に晴らす「解放」フェーズが交互に訪れるか？

### #03 RPGのゲーム性（リソースと引き際のチキンレース）
- **核心**: RPGのゲーム性もリスクとリターン。奥へ進むほど敵は強く全滅のリスクが高まるが、手に入る経験値や宝は増える。「無理して進むか、安全なうちに引き返すか」の境界線で迷わせることで面白さが生じる。
- **Core Skill**: **不可逆性（コミットメント）と損切り判断の設計**
- **AIへの実装・指示原則**:
  - ダンジョン攻略やステージ進行において、「全滅時のペナルティ（所持金半減、戦利品ロストなど）」と「撤退による保全」の選択肢を常に提示する。
  - 回復リソース（MP、ポーション）を有限化し、深度（Depth）が増すごとに消費ペースを加速させる計算式を組ませる。
- **アンチパターン**:
  - いつでもノーコスト・無制約で全回復・脱出でき、進退を悩む理由が一切存在しない設計。
- **チェックリスト**:
  - [ ] 「これ以上進むと失うものが大きいが、行けば手に入る」という葛藤が数値モデルとして機能しているか？

### #04 ゲーム性以外の面白さ（複合的魅力のレイヤー化）
- **核心**: ゲーム性（駆け引き・リスク＆リターン）は面白さのすべてではない。操作の快感、物語、ビジュアル、キャラ、実在モチーフの再現、クラフト、音など、ゲーム性以外の楽しさ（7つの要素）が合わさって作品が成り立つ。
- **Core Skill**: **面白さの主従定義（プライマリ動機の選定）**
- **AIへの実装・指示原則**:
  - 「このゲームが提供する第一の快感は何か」を明確に定義する（駆け引き、操作の手触り、世界観再現など）。
  - シミュレータやビジュアルノベル等では無理に複雑なリスク＆リターンを詰め込まず、挙動の忠実度や音響・演出の応答性（触感）にリソースを集中させる。
- **アンチパターン**:
  - 爽快なクラフトや物語鑑賞を楽しみたいゲームに、過剰で不親切な駆け引きやシビアな即死ギミックを混入させて体験を損なう。
- **チェックリスト**:
  - [ ] 仕様策定時に「ゲーム性の高さ」と「手触り・演出の良さ」のどちらを最優先すべきか、軸がぶれていないか？

### #05 悪魔の釜（自発的リスク設定と難易度動態）
- **核心**: 『新・光神話 パルテナの鏡』の難易度システム「悪魔の釜」のように、プレイヤー自身がリソースを賭けて難度（ホンキ度）を決定する。ハイリスク・ハイリターンを自発的に選ばせ、ミスしたら自動的に難度が下がっていくため、屈辱的な「イージーにしますか？」を出さずに済む。
- **Core Skill**: **プレイヤー駆動型ダイナミック難易度調整（DDA）**
- **AIへの実装・指示原則**:
  - 固定難易度選択（Easy/Normal/Hard）ではなく、「ゲーム内通貨やスコア倍率を賭けて難易度スライダーを動かす」メカニクスを設計する。
  - 失敗時のロジック：ゲームオーバーで突き放すのではなく「賭けたリソースを没収した上で、難易度ランクを1段下げて即座に同地点から再開」させる。
- **アンチパターン**:
  - 敗北時に「難易度を下げて再挑戦しますか？」とダイアログで確認し、プレイヤーの自尊心を傷つける。
- **チェックリスト**:
  - [ ] 上級者が自発的にハイリスクを選び、初心者が自然に保護されるインセンティブ構造になっているか？

### #06 ズルを許す（抜け道とエクスプロイトの受容）
- **核心**: 攻略の本質は「損をせず得をすること」。プレイヤーは必死で得をする手段＝「ズル（安全地帯、特定ハメ技、メタルスライム狩り）」を探す。バランスを壊すからと完全に平坦にデバッグし切ると、ゲームから発見の喜びが失われる。
- **Core Skill**: **非対称な有利ポイント（意図的アンバランス）の配置**
- **AIへの実装・指示原則**:
  - 数学的に完璧な均一バランスを目指すのではなく、特定の手順や位置取りに気づいたプレイヤーが「一方的に有利になれるボーナス解法」をあえて1〜2箇所残す。
  - 希少で倒しにくいが莫大なリソースを落とすボーナス対象（メタルスライム型エンティティ）を確率出現させる。
  - ※メモリ破壊やゲーム進行不能などの致命的バグは防ぎつつ、「ルール内の極端な有利」をゲームデザインとして許容する。
- **アンチパターン**:
  - プレイヤーが見つけた効率的なファーミングや戦法を、開発都合で「想定外の挙動」としてすべてパッチで平坦に均してしまう。
- **チェックリスト**:
  - [ ] プレイヤーが「賢い攻略法（ちょっとしたズル）を発見した！」と錯覚できる余白が用意されているか？

### #07 敵がいる意味（動的プレッシャーと行動の強制）
- **核心**: 敵は単なる標的ではなく、「プレイヤーにリスクを突きつけ、移動や回避を強いる動的な障害物」。敵がいなければ探索は単なる移動作業になり、定位置からの射撃だけで終わる。敵がプレイヤーの安全地帯を崩すことで意思決定が発生する。
- **Core Skill**: **敵エンティティによる安全地帯破壊設計**
- **AIへの実装・指示原則**:
  - 敵AIを「プレイヤーを倒すルーチン」ではなく「プレイヤーの現在地を危険にし、別の座標への移動や別アクションを強要するトリガー」として組む。
  - プレイヤーが同じ安全行動（画面端での待ち、特定遠距離攻撃の連打）を維持した際、それを崩すカウンター行動（突進、ガード貫通、範囲爆撃）を各敵種に1つ以上割り当てる。
- **アンチパターン**:
  - プレイヤーの居場所や行動に干渉せず、決められたルートを往復して撃破されるだけの的（環境オブジェクト以下の敵）。
- **チェックリスト**:
  - [ ] 各敵の行動ルーチンが、プレイヤーに具体的な操作（跳ぶ、退く、接近する、守る）を強制させているか？

### #08 3すくみ・相性（支配的戦略の解体）
- **核心**: 格闘ゲームの「打撃・ガード・投げ」に代表されるじゃんけん構造（3すくみ）。万能の最強行動（支配的戦略：Dominant Strategy）をなくし、相手の手を読んで選択肢を変える「読み合い」を生み出す。
- **Core Skill**: **循環型ステート相性マトリクス（Rock-Paper-Scissors）の実装**
- **AIへの実装・指示原則**:
  - 主要アクションを属性A, B, Cに分類し、`A beats B, B beats C, C beats A` の循環関係を定義する。
  - 状態遷移において、「ガード硬直中は投げ判定に対して無防備」「大技の発生フレーム中は小技で割り込み可能（発生勝ち）」といった排他的判定をコードレベルで厳密にバインドする。
- **アンチパターン**:
  - 攻撃力が高く、硬直が短く、すべての迎撃手段を潰せる「出得（だしどく）」な万能コマンドの放置。
- **チェックリスト**:
  - [ ] どの強力な行動にも、それを低コストで潰せるカウンター行動が必ず存在しているか？

---

### #09 運と実力のバランス（不確実性による包摂とドラマ）
- **核心**: 100%実力だけのゲームは初心者が上級者に勝てず間口が狭まる。マリオカートのアイテムのように、適度な運（不確実性）を介在させることで実力差を緩和し、逆転のドラマを生む。ただし、理不尽な運負けにしてはならない。
- **Core Skill**: **入力ランダム性の優先とラバーバンディング（劣勢補正）**
- **AIへの実装・指示原則**:
  - 攻撃の命中判定など行動結果をサイコロで決める「出力の運」を極力排除し、配られる手札や出現アイテムが変化する「入力の運」を主軸にする。
  - スコアや順位の劣勢度合いに応じて、下位プレイヤーに強力な支援アイテムの出現率を上げる補正計算式（ラバーバンド効果）を組み込む。
- **アンチパターン**:
  - プレイヤーが完璧な立ち回りをしたにもかかわらず、低確率のランダム即死や完全乱数で敗北する理不尽設計。
- **チェックリスト**:
  - [ ] ランダム要素を引いた後、プレイヤーが「この配牌・状況をどう打開するか」を思考・介入できる余白があるか？

### #10 予兆とリアクション（納得感を生む猶予フレーム）
- **核心**: 敵が予備動作なしで急に攻撃してくると、プレイヤーは理不尽と怒りを感じる。大技ほど「溜めモーション」「発光」「警告音」などの予兆（テレフォンパンチ）を明確にし、人間が見てから対処（回避・防御）できる時間を保証する。
- **Core Skill**: **テレグラフ（予兆）と反応猶予（Reaction Window）の保証**
- **AIへの実装・指示原則**:
  - 攻撃ロジックを `Windup（予兆） -> Active（判定発生） -> Recovery（後隙）` の3段階に厳格分離する。
  - 人間の視覚反応速度（約0.2〜0.3秒 = 12〜18フレーム/60fps）を基準とし、見てから避けるべき強攻撃のWindupは最低でも15フレーム以上確保させる。高威力な技ほど予兆と後隙を長く設定する。
- **アンチパターン**:
  - 発生1〜2フレームで画面全体を薙ぎ払う攻撃など、事前の予測・反応が物理的に不可能な攻撃の実装。
- **チェックリスト**:
  - [ ] ダメージ発生前に、視覚的（チャージ演出・モーション）および聴覚的（SE）サインが先行して提示されているか？

---

### #11 リトライの快適さ（試行錯誤の摩擦ゼロ化）
- **核心**: ゲームオーバーやミス自体は問題ではない。最もプレイヤーの意欲を削ぐのは「ミスした後に再挑戦するまでの待ち時間と手間」。即座にリスタートさせ、失敗から得た気づきが冷めないうちに再挑戦させることが熱中を生む。
- **Core Skill**: **失敗摩擦（Retry Friction）の極小化アーキテクチャ**
- **AIへの実装・指示原則**:
  - ミス発生からリスタートまでの時間を最小化する（不要なリザルト演出のスキップ化、アセットの非同期事前ロード、演出カット機能）。
  - チェックポイントは「難所の直前」に自動配置し、難所に挑む前の平坦な移動や前座の雑魚戦を何度もやり直させない。
- **アンチパターン**:
  - 失敗するたびに演出ロゴを長々と見せ、タイトル画面や遠い拠点まで強制送還する設計。
- **チェックリスト**:
  - [ ] プレイヤーが死亡してから再操作可能になるまでの復帰シーケンスが数秒以内に完了しているか？

---

### #12 残機とゲームオーバー（レガシー要素の機能再定義）
- **核心**: アーケード時代のインカム維持から生まれた「残機システム」は、現代ゲームでは単なるセーブ巻き戻しの作業になりがち。緊張感を生む目的がないなら、残機は撤廃するか、スコアやランクの減点要素へ再定義すべき。
- **Core Skill**: **ペナルティの目的別選定（進行停止からスコア評価へ）**
- **AIへの実装・指示原則**:
  - 惰性で「残機（Lives）」を導入させない。採用する場合は「1ステージ（1チェックポイント間）で許容されるミス回数」として局所化し、ゲーム全体のやり直しを強制させない。
  - デフォルト設計としては「進行は無制限に許可し、ミス回数に応じてクリアランクや追加リソースを減らす」評価連動ペナルティを採用する。
- **アンチパターン**:
  - 残機が0になったらセーブデータをロードして同じ場所へ戻ってくるだけの、形骸化した残機・ゲームオーバー表示。
- **チェックリスト**:
  - [ ] 残機やゲームオーバーの存在が、単なる「時間の浪費」ではなく「現在のプレイの緊張感」として機能しているか？

---

### #13 連射と溜め攻撃（単一入力による戦術的分岐）
- **核心**: 通常射撃（低威力・低リスク・連射）と溜め射撃（高威力・高リスク・単発）。同じ攻撃ボタンでも「タップ」と「ホールド」で役割を分けることで、状況に応じて手数を優先するか一撃を狙うかの判断が生まれる。
- **Core Skill**: **単一キーの多重化（Modal Input）によるリスク管理**
- **AIへの実装・指示原則**:
  - 入力バッファに短押し（Tap）と長押し（Hold）の判定を設け、1つのボタンで速射とチャージ攻撃を切り替え可能にする。
  - チャージ中は移動速度低下や回避不可といった制約（リスク）を課し、雑魚戦では速射、ボスの隙やダウン時には溜め攻撃という使い分けの文脈を成立させる。
- **アンチパターン**:
  - 溜め攻撃の威力設定が甘く、単に連射した方が時間あたりのダメージ効率（DPS）が高い調整。
- **チェックリスト**:
  - [ ] 敵の隙の大きさに応じて、プレイヤーがタップ攻撃と溜め攻撃を能動的に使い分ける動機があるか？

---

### #14 初心者救済とハンディキャップ（実力格差の吸収）
- **核心**: 対戦や協力プレイで実力差がそのまま結果に出続けると、初心者は楽しめず離脱する。スマブラの蓄積ダメージによるふっとびやすさやハンデ機能のように、負けている側が自然と一矢報いることができるシステムが必要。
- **Core Skill**: **動的平衡化（Dynamic Handicap）の組み込み**
- **AIへの実装・指示原則**:
  - 対戦・マルチプレイにおいて、キル/デス比やスコア差に応じて、劣勢側の攻撃力バフ、被ダメージ補正、ゲージ充填速度向上を動的に付与する。
  - 単純な体力制ではなく、場外落下やリングアウトなどの物理挙動を採用し、上級者相手でも初心者が地形やアイテムを利用したラッキーヒットで勝利できる余地を残す。
- **アンチパターン**:
  - 復活した瞬間に即座に上級者から狩られ続ける、リスキル対策や無敵時間のない対戦環境。
- **チェックリスト**:
  - [ ] 実力差がある状態でも、初心者が「手も足も出ない」状態にならず、ゲームに関与できている手応えを得られるか？

---

### #15 即死・落下死の功罪（極限リスクの透明性）
- **核心**: 一撃死や足場からの落下死は、一瞬で最大のリスクをもたらし緊張感を高める強力なスパイス。しかし、画面外からの不意打ちや見えない穴による即死は強い理不尽感を生むため、配置には事前の視覚提示と納得感が必須。
- **Core Skill**: **致死ハザード（Lethal Hazard）の視覚的透明性とセーフティ網**
- **AIへの実装・指示原則**:
  - 即死トラップや落とし穴の周囲には、明確な予兆（色、警告マーク、ひび割れた床）を常時表示させる。
  - 一発で即死させるのではなく、「1回踏み外しても壁キックや復帰技で復帰可能な猶予」「ダメージを受けて足場に跳ね返る多段階セーフティ」を設ける。
- **アンチパターン**:
  - カメラの死角に穴が配置されており、ジャンプして初めて落ちることが判明する「見えない落下死」。
- **チェックリスト**:
  - [ ] 即死でミスした際、プレイヤーが「システムが理不尽」ではなく「自分の操作ミス」として100%納得できる設計か？

### #16 待ちの強さ（タートル戦術の打破と攻勢誘導）
- **核心**: 対戦やアクションで「守ってカウンターを狙う（待ち）」が最強になると、双方が動かなくなりゲームが完全に膠着する。攻める側に明確なメリットを与えるか、守り続ける側にペナルティを課して前進を促す仕組みが不可欠。
- **Core Skill**: **アグレッシブ・インセンティブ（攻勢誘導）の設計**
- **AIへの実装・指示原則**:
  - ガード行動に耐久値（シールドゲージ）を設け、連続使用でシールドブレイク（無防備スタン）を発生させる。
  - 前進・攻撃を継続することで上昇するバフゲージ（攻撃力UP、機動力UP）や、消極的な後退・引きこもりに対して付与されるデバフ（リソース減少、ネガティブペナルティ）を状態遷移に組み込む。
- **アンチパターン**:
  - 防御や遠距離牽制の隙が極端に短く、守り側の勝率が攻め側を圧倒してしまう静止状態の放置。
- **チェックリスト**:
  - [ ] 守り続けることが「最も効率的な解」になってしまっていないか？ 攻めた側が得をする動機があるか？

### #17 制限時間の意味（意思決定の加速と停滞排除）
- **核心**: タイムリミットは単なるゲームオーバー条件ではない。無限の長考や安全策によるダラダラプレイを断ち切り、プレイヤーに適度な焦燥感と集中力を与え、素早い決断を迫るための調律装置。
- **Core Skill**: **デシジョン・プレッシャー（時間制約）の調律**
- **AIへの実装・指示原則**:
  - 単純なゲームオーバータイマーにするだけでなく、「残り時間が減るほど敵の攻撃頻度が上がる」「制限時間内にクリアすると高ランク・限定報酬」といった多層のインセンティブを設計する。
  - 探索や謎解きなど「じっくり考えること」が主目的のフェーズでは不要な時間制限を撤廃し、戦闘や脱出など「瞬発的な判断」を求めるフェーズに絞ってタイマーを適用する。
- **アンチパターン**:
  - 試行錯誤や観察を楽しませるパズル・探索ステージに、猶予のないシビアなタイマーを無目的に課す。
- **チェックリスト**:
  - [ ] 制限時間の存在が、プレイヤーの操作テンポを加速させ、スリルを高める機能として働いているか？

### #18 体感確率（認知バイアス適応型乱数）
- **核心**: 人間の体感は数学的確率と一致しない。「命中率95%」で外れると激怒し、「10%」の敵の攻撃が2連ヒットすると不正を疑う。プレイヤーにストレスを与えず納得感を持たせるには、純粋乱数ではなく「体感に寄せた補正」が必要。
- **Core Skill**: **擬似乱数（Pseudo-Random Distribution）とバイアス補正**
- **AIへの実装・指示原則**:
  - 一様乱数（Pure Random）をそのまま使わず、連続で失敗した場合は次回の成功確率を段階的に引き上げる補正ロジック（PRD）を組む。
  - 「命中率90%以上」の演出は体感的には100%に近いため、裏で実確率を95〜98%に底上げし、「10%以下」の危険イベントは連続発生しないようクールダウンを設ける。
- **アンチパターン**:
  - 「数学的に正しいから」と一様乱数をそのまま適用し、90%の攻撃が3連続で外れてプレイヤーの戦術プランを破綻させる。
- **チェックリスト**:
  - [ ] クリティカルや命中・ドロップ判定に、連続失敗時の救済や体感確率との乖離を埋める補正が入っているか？

### #19 必殺技ゲージ（逆転の契機とカタルシス）
- **核心**: ダメージを受ける、あるいは攻め続けることで溜まるリソースゲージ（超必殺技・最後の切り札）。負けている側が一発逆転を狙える希望を生み、単調な削り合いに大きな山場（ドラマ）を作る。
- **Core Skill**: **クライマックス・リバーサル（逆転トリガー）の動力学**
- **AIへの実装・指示原則**:

  - 発動時は時間停止演出、広範囲攻撃、無敵フレームなど圧倒的な制圧力（カタルシス）を与える一方、空振りやガードされた際の後隙を特大にし、「ハイリスク・ハイリターンの大博打」として着地させる。
- **アンチパターン**:

- **チェックリスト**:

### #20 選択肢の絞り込み（認知的負荷の最小化）
- **核心**: 行動の選択肢が多すぎると、プレイヤーは選べず思考停止に陥る（選択の麻痺）。人間が瞬時に判断できる選択肢は限られているため、1つの場面で提示する選択肢は2〜3個、多くても4個以内に整理しなければならない。
- **Core Skill**: **コグニティブ・ロード（思考負荷）の削減と動的コンテキスト化**
- **AIへの実装・指示原則**:
  - 基本操作ボタンに割り振るメイン動詞を「攻撃・ジャンプ・防御（または回避）」の3つ前後に絞り込む。
  - 多彩なスキルを持たせる場合は、常時画面に並べるのではなく「状況（ジャンプ中、ガード中、特定距離）に応じて同じボタンの役割が自動で切り替わる」コンテキストドリブンな設計にする。
- **アンチパターン**:
  - 戦闘中に画面下部へ10個以上のアイコンが並び、ショートカットキーの判別に視線と思考が奪われる過密UI。
- **チェックリスト**:
  - [ ] プレイヤーが咄嗟の状況で選ぶべき手数が、瞬時に認知可能な数（3択以内）に収まっているか？

### #21 成長とインフレ（質的拡張によるスケール設計）
- **核心**: レベルアップで単に攻撃力やHPの数値を何倍にも増やすだけだと、過去の敵が一撃で溶けるか、敵のHPも同じ倍率で増えて「数字の桁が増えただけの作業」になる。数値のインフレではなく「できる行動の幅」を増やすべき。
- **Core Skill**: **横方向の拡張（Horizontal Progression）とスケーリング統制**
- **AIへの実装・指示原則**:
  - 成長報酬を「ステータス+10%」といった量的増加ではなく、「2段ジャンプ解禁」「攻撃後のダッシュキャンセル可能」「属性付与」といった**立ち回りの選択肢を増やす質的解禁**にする。
  - 数値スケーリングを行う場合も、計算式に減衰曲線（Diminishing Returns）を適用し、序盤のエリアや敵が完全に無意味化しないバランスを保つ。
- **アンチパターン**:
  - ダメージの桁だけが100から100万に膨れ上がり、本質的な駆け引きや攻略手順が序盤と一切変わらないインフレ。
- **チェックリスト**:
  - [ ] レベルや強化によって、プレイヤーの「プレイスタイルや戦術の選択肢」が実際に増えているか？

### #22 テンポと硬直（ヒットストップによる打撃感の創出）
- **核心**: 攻撃が当たった瞬間に、あえて双方の時間を数フレームだけ止める「ヒットストップ」。攻撃の手応え（重み・感触）を生み出すと同時に、プレイヤーに「命中した」事実を認識させて次の入力判断を行う猶予を与える。
- **Core Skill**: **キネティック・フィードバック（打撃硬直）のフレーム制御**
- **AIへの実装・指示原則**:
  - 攻撃判定（Hitbox）が食らい判定（Hurtbox）と交差した瞬間、アニメーション再生を3〜8フレーム停止させるグローバル時間遅延を組み込む。
  - 軽攻撃は短く（1〜3フレーム）してテンポを保ち、重攻撃や必殺技は長く（8〜12フレーム）＋カメラシェイクを連動させてインパクトの重みを演出する。
- **アンチパターン**:
  - 攻撃が命中しても何の引っかかりや反動もなく、紙を切るように敵をすり抜けていく感触のない当たり判定。
- **チェックリスト**:
  - [ ] 一撃ごとの威力差が、アニメーションの「止め（ヒットストップ時間）」の長さで直感的に伝わっているか？

### #23 遊びの核（マイクロ・コアループの純化）
- **核心**: ゲームの面白さの本質は、プレイ中に最も高頻度で繰り返される「数秒〜数十秒のループ（行動→フィードバック→快感）」。外装（ストーリー、美麗なグラフィック、育成要素）をすべて剥ぎ取っても、この核単体で楽しいかどうかが成否を決める。
- **Core Skill**: **マイクロ・コアループ（最小反復快感サイクル）の自律検証**
- **AIへの実装・指示原則**:
  - プロトタイプ作成時、グラフィックやストーリーを一切入れず、仮の幾何学図形（プレースホルダー）だけで「動かす・当てる・避ける」の基本サイクルを組ませる。
  - 1ループの所要時間を5〜15秒に設定し、「課題提示（敵接近）→ 操作実行（回避・射撃）→ 結果（撃破の爽快感）」が淀みなく循環する状態を検証させる。
- **アンチパターン**:
  - 派手な演出や複雑な設定を先に作り込み、肝心の「コントローラーを握って動かす数秒間」が退屈なまま進行する。
- **チェックリスト**:
  - [ ] すべての演出・育成・ストーリーをオフにして、幾何学ブロックだけの状態でも操作そのものが面白いか？
