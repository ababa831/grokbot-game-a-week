# 操作感・触感・時間・カメラ仕様リファレンス（Game Feel & Controls）

YouTube「桜井政博のゲーム作るには」に基づく手触り・操作感の8大原則。
アクション挙動の実装、物理演算の調整、カメラ制御、UI遷移、ポーズ・スキップの実装時に参照する。

---

### #01 大事なところはストップ！（ヒットストップとインパクト演出）
- **核心**: 攻撃が命中した瞬間やボス撃破、被弾の瞬間は「あえて時間を止める（ストップ演出）」。時間を止めることで、プレイヤーは「命中した（してやったぞ感）」「やられた（しまった感）」を認識し、感覚が増幅される。動かし続けると手応えが消え、何が起きたか分からなくなる。
- **Core Skill**: **時間凍結（Freeze Frame）とインパクトの分離制御**
- **AIへの実装・指示原則**:
  - 命中判定（Collision）発生時、全体時間を止めるのではなく、**「攻撃側」と「被弾側」のアニメーション更新のみを数フレーム（3〜10F）停止**させる独立タイマーを実装する。
  - **ストップ中**: 被弾エンティティに微小なランダム座標オフセット（振動・シェイク）を適用する。
  - **ストップ終了フレーム**: ノックバック速度ベクトルと被弾エフェクトを一気に適用し、弾け飛ぶ勢いを強調する。
  - *注意*: 停止中もポーズUIや解除タイマーは更新を継続すること。
- **アンチパターン**:
  - 攻撃が当たってもキャラクターが滑らかに動き続け、ヒットしたかどうかがHPバーの減少でしか認識できない「スカスカな打撃感」。
- **AIレビュー用チェックリスト**:
  - [ ] 攻撃命中時に、攻撃者と被災者の双方が数フレーム静止するヒットストップ処理が組み込まれているか？
  - [ ] ボス撃破や強攻撃のクリティカル時に、画面全体のわずかなスローまたは静止演出が入っているか？

### #02 物理ボタンに重たさを感じさせる（重量感の錯覚生成）
- **核心**: コントローラーのボタンは均一なプラスチックの軽いスイッチに過ぎない。だが「押してから動き出すまでの予備動作のタメ」「振り切る速度」「重厚なSE」「画面の揺れ」を連動させることで、プレイヤーの脳内に「重い物体を動かしている手応え」を錯覚させることができる。
- **Core Skill**: **視聴覚連動による疑似触覚（Pseudo-Haptic）の実装**
- **AIへの実装・指示原則**:
  - 重い攻撃や大型武器の操作時、入力直後（Frame 0）で即座に攻撃判定を出さず、長めの予備動作（Windup: 10〜20F）をあえて入れる。
  - 振り抜く瞬間（Active Frame）は一瞬（1〜2F）で遷移させ、命中時に重低音SE＋カメラシェイク（Camera Shake）を同期発火させる。
  - コントローラーの振動（Rumble/Haptics）を利用可能な場合、入力時（弱振動）→ 溜め中（リニア上昇）→ 命中時（強パルス）とフェーズを分ける。
- **アンチパターン**:
  - 大剣を振るう動作なのに、ナイフと同じ速度でスイングが始まり、重力や慣性を感じさせない等速アニメーション。
- **AIレビュー用チェックリスト**:
  - [ ] 「重い」アクションにおいて、予備動作のタメ（低速）と解放（高速）のコントラストが極大化されているか？

---

### #03 ジャンプのしくみ（物理法則の意図的歪曲）
- **核心**: 物理学通りの純粋な放物線ジャンプは、ゲーム内では「もっさりして着地が遅い」「空中制御が効かず不快」に感じられる。ボタンを押す長さで高さを変え、上昇時よりも下降時の重力を重くしてキビキビ着地させることで、意のままに動く操作感を生み出す。
- **Core Skill**: **非対称ジャンプ物理と寛容性入力（Forgiveness）**
- **AIへの実装・指示原則**:
  - **非対称重力**: 上昇中（`velocity.y > 0` または画面座標で上方向）の重力加速度に対し、下降中の重力加速度を **1.5〜2.0倍** に引き上げ、キビキビと素早く着地させる。
  - **可変ジャンプ**: ジャンプボタンを途中で離した場合、上昇速度を強制的に一定割合カット（例: `velocity.y *= 0.5`）して低ジャンプにする。
  - **コヨーテタイム（Coyote Time）**: 足場から落下した後、数フレーム（例: 5〜8フレーム / 約0.1秒）以内であれば空中であってもジャンプ入力を受け付ける。
  - **先行入力バッファ（Jump Buffer）**: 着地する数フレーム前に入力されたジャンプ入力を保持し、着地した瞬間に自動でジャンプを発動させる。
- **アンチパターン**:
  - 物理演算エンジン（Rigidbody等）のデフォルト設定をそのまま使い、空中での軌道修正が一切効かない、または落下がふわふわしているジャンプ。
- **AIレビュー用チェックリスト**:
  - [ ] 下降速度が上昇速度よりも速く調整されているか？
  - [ ] コヨーテタイムと先行入力バッファが実装され、崖際や着地前の操作取りこぼしが防止されているか？

### #04 ガケぎわのふるまい（理不尽な落下の排除）
- **核心**: プレイヤーは精密機械ではないため、1ピクセルの誤差で崖から滑り落ちると「操作性が悪い」と感じてしまう。崖の縁では足を踏みとどまらせる、あるいはジャンプで飛び移る際に崖の端へ自動で吸着・掴まり判定を持たせるなど、プレイヤーの意図を汲む支援が必要。
- **Core Skill**: **エッジ・アシスト（崖際スナッピング＆セーフティ）**
- **AIへの実装・指示原則**:
  - 通常歩行時、崖の端に到達した際にスティックの深い入力がない限り、落下せずに縁で止まるブレーキ判定（Edge Stop）を設ける。
  - 足場へ向かってジャンプした際、わずかに距離が足りなくても崖の角を掴んで登る「崖掴まり（Ledge Grab）判定」をキャラクターのコライダー上部に追加する。
  - 壁に接触しながら落下する際、下向きの重力を弱める「壁滑走摩擦」を付与し、即座の落下死を防ぐ。
- **アンチパターン**:
  - 足場の角が滑りやすく設定されており、端に立っただけでツルッと滑落して死亡・被弾するシビアすぎる物理境界。
- **AIレビュー用チェックリスト**:
  - [ ] プレイヤーが「届くと思った」ジャンプ軌道に対し、崖際でわずかに救済される吸着・掴まり判定が存在するか？

### #05 注視点をくっつけない（カメラの遊びと先読み）
- **核心**: カメラの注視点をプレイヤーキャラクターの中心に完全固定（リジッドにバインド）すると、キャラが動くたびに画面全体がガタガタと揺れ、3D酔いや激しい疲労を引き起こす。カメラには適度な遊び（デッドゾーン）を持たせ、キャラではなく「キャラの進行方向の先」を見せるべき。
- **Core Skill**: **デッドゾーン・ダンピングと進行方向オフセット**
- **AIへの実装・指示原則**:
  - カメラ追従にデッドゾーン（移動の遊び領域）を設定し、キャラクターがその中心枠から出るまではカメラ座標を静止させる。
  - 追従開始時は線形移動ではなく、`SmoothDamp` や時間依存の減衰関数を用いて遅延させながら滑らかに追いつかせる（フレームレート非依存の補間）。
  - 水平移動時、キャラの現在座標ではなく「移動方向の先（Look-Ahead Offset: 数メートル/数百ピクセル先）」にカメラのターゲット座標を動的にシフトさせ、進行方向の視界を広く確保する。
- **アンチパターン**:
  - キャラクターの頭部にカメラのLookAtを1対1で固定し、小刻みな足踏みやジャンプのたびに画面全体が小刻みに上下運動する設計。
- **AIレビュー用チェックリスト**:
  - [ ] キャラクターが進行方向へ走り出した際、画面中央よりも「進行方向の先」が広く映し出されているか？

---

### #06 遅さは罪・画面遷移は素早く（入力応答性の最大化）
- **核心**: メニューを開く、ページをめくる、決定を押すといったUI操作において「もっさりした遅さ」は純粋なストレスであり悪。おしゃれなアニメーションを見せるためにプレイヤーの操作を待たせてはならない。画面遷移やカーソル移動は極力ゼロディレイでパッと切り替わるべき。
- **Core Skill**: **ゼロ待機UIアーキテクチャと割り込み許可**
- **AIへの実装・指示原則**:
  - メニュー階層の開閉やタブ切り替えのアニメーションは**最長でも0.1〜0.15秒（6〜10フレーム）以内**に収める。
  - トランジション演出（フェードイン/アウトなど）の再生中であっても、決定キー連打や先行入力を破棄せず、演出を即座に最終フレームへスキップして次の入力を受け付ける。
  - ポーズメニューの呼び出しは、処理負荷に関わらずボタンを押した同一フレーム内で即座にゲーム内時間を止め、UIを表示する。
- **アンチパターン**:
  - メニューの項目を選ぶたびに、フワッとしたフェードアニメーションが完了するまで次のカーソル移動がブロックされるUI。
- **AIレビュー用チェックリスト**:
  - [ ] プレイヤーがボタンを連打した際、演出の再生完了を待たずに即座に次画面へ遷移できるか？

### #07 わかりやすさとスタイル性（機能美とフォント視認性）
- **核心**: UIで最も大切なのは「わかりやすさ（視認性・可読性）」であり、デザインのおしゃれさ（スタイル性）は二の次。世界観を表現しようとして文字を小さくしたり、装飾過多で背景と同化したりしてはならない。離れた画面や小さなモニターでも一瞬で状況が伝わることが大前提。
- **Core Skill**: **ハイコンテキストな視覚的階層化（Visual Hierarchy）**
- **AIへの実装・指示原則**:
  - **文字の大きさ保証**: ゲーム画面内のテキストは、想定最小解像度（ポータブル機やスマートフォン、離れたTV画面）を基準に設計し、極小フォントを使用しない。
  - **明度コントラスト**: テキストや重要アイコンの背景には、半透明の黒帯（グラデーションプレート）や縁取り（アウトライン）を敷き、明るいステージでも暗いステージでも視認性を100%維持する。
  - 重要パラメータ（HPの枯渇、制限時間切れ間近など）は、色変化だけでなく「点滅」「拡縮アニメーション」を組み合わせて周辺視野でも異変に気づけるようにする。
- **アンチパターン**:
  - 背景の3Dモデルやエフェクトに溶け込むような、極細フォントや縁取りのない淡い配色のUIデザイン。
- **AIレビュー用チェックリスト**:
  - [ ] 激しいエフェクトや背景の明暗変化の中でも、HPや弾薬などの重要情報が一瞥で読み取れるか？

---

### #08 必ず飛ばせる・止められる（プレイヤーフリーダムの保証）
- **核心**: ゲームは能動的なメディアであるため、プレイヤーから操作権を奪い続けることは強い苦痛となる。イベントシーン、会話テキスト、ロゴ表示などは「いつでもスキップ・早送りできる」「いつでもポーズで中断できる」仕組みが必須。
- **Core Skill**: **ステート完全ポーズ機能とスキップ・ハンドラ**
- **AIへの実装・指示原則**:
  - 会話ダイアログには「1文字ずつ表示の瞬間スキップ（全文一括表示）」と「次の台詞への即時進行」を実装する。
  - カットシーンやイベント演出には、単一ボタン長押しまたはポーズメニューからの「シーンスキップ」ハンドラを常時バインドする。
  - ポーズ中はゲーム内のあらゆるTick（物理演算、パーティクル、タイマー、入力判定）を安全に凍結し、再開時に位置や速度が狂わないようステートを完全保持する。
- **アンチパターン**:
  - ボス戦直前の会話や演出がスキップ不可能で、リトライするたびに同じ会話を何度も強制的に見せられる設計。
- **AIレビュー用チェックリスト**:
  - [ ] ゲーム内のすべての非操作フェーズ（会話・デモ・オープニング）に、スキップおよび一時停止の手段が存在しているか？
