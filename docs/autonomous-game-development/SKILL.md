# 自律ゲーム開発（Autonomous Game Development）

桜井政博氏のゲーム制作哲学・設計知見（「桜井政博のゲーム作るには」）を体系化し、AIが自律的に「面白い・手触りの良いゲーム」を企画・実装・検証・改善するための開発プロトコル。

AIに愚直に物理演算や入力受付をコード生成させると、「硬い・もっさりしている・操作していて気持ちよくない・退屈な作業」になりがちである。本スキルは、**物理法則の意図的歪曲（非対称ジャンプ・ヒットストップ・コヨーテタイム）**、**駆け引きの本質（リスク＆リターン・緊張と緩和）**、**手戻りゼロの逆算設計（ペラ1枚企画・決定論的仕様）**をAIが自律的に適用するための規範を提供する。

---

## 自律開発の5段階ループ（Autonomous Game Dev Loop）

自律的にゲームを制作・改善する際は、以下の5フェーズを順に回す。限定された依頼（「ジャンプの調整だけ」「企画書だけ」等）の場合は、該当フェーズのみを実行する。

```
[Phase 1: 企画策定] ──> [Phase 2: 決定論的仕様] ──> [Phase 3: 最小実装]
        ^                                                   │
        │                                                   v
[Phase 5: 手触り・ゲーム性改善] <── [Phase 4: 操作観測・実機検証]
```

### Phase 1: 遊びの仮説と核の固定（Planning）
1. **ペラ1枚で全容を定義する**: 長大な文書を作らず、[templates/one-sheet-plan.md](templates/one-sheet-plan.md) に従い「①ゲームの核（一文）」「②基本画面レイアウト（ASCIIアート）」「③コアループ（3ステップ）」「④独自性（1点）」のみを定める。
2. **イミュータブル・コアバリュー（不変の主目的）の策定**: 「このゲームは〇〇を楽しむゲームである」を一文の定数として固定する。以降の機能追加は、この核を直接強化するもののみ採用し、薄いものは却下する。
3. **引き算と組み合わせ**: 既存要素を多目的化（1つのボタン・オブジェクトに複数の役割を持たせる）し、新ルールを足す代わりに既存機能を簡素化する。
4. **ターゲットとスキルキャップの固定**: 初心者向けか熟練者向けかを定め、同時入力数や画面内情報量の上限値を決める。
- *詳細リファレンス*: [references/planning.md](references/planning.md)

### Phase 2: 決定論的仕様の策定（Specifications）
1. **曖昧なポエムの排除**: 「適度に」「かっこよく」「敵が怒る」といった自然言語を禁止する。[templates/deterministic-spec.md](templates/deterministic-spec.md) を用い、状態遷移図、入力マトリクス、単位付きパラメータ表で定義する。
2. **境界条件（Edge Cases）の先回り網羅**: 同時押し優先度、画面端座標クランプ、HPゼロと同時の命中、ポーズ中の入力処理を確定させる。
3. **完成形からの逆算（バックキャスティング）**: タイトル→プレイ→ゲームオーバー/クリア→再開の閉じた遷移マップを先に確定させ、途中でのFeature Creep（際限ない仕様追加）を防ぐ。
- *詳細リファレンス*: [references/planning.md](references/planning.md)

### Phase 3: 最小プロトタイプの自律実装（Minimal Prototyping）
1. **単一の仮説検証に特化（使い捨て精神）**: 美麗なグラフィックや凝ったUI・音響を入れず、幾何学図形（四角・円・ワイヤーフレーム）のみで構築する。「この操作・コアループは本当に面白いか？」の1点だけを検証する。
2. **手触り（Game Feel）の初期定数の組み込み**:
   - 非対称重力（下降重力 = 上昇重力の 1.5〜2.0倍）
   - コヨーテタイム（足場離脱後 5〜8フレーム猶予）
   - 先行入力バッファ（着地前 5〜8フレーム保持）
   - ヒットストップ（命中時アニメーション 3〜10フレーム凍結）
3. **固定タイムステップ（Fixed Tick）の徹底**: 描画フレームレートに物理挙動やタイマーを依存させず、Δt基準または固定周波数（60Hz基準等）で計算する。

### Phase 4: 操作観測と実機検証（Observation & Verification）
1. **テスト成功と面白さの混同禁止**: 単体テストのパスやコード読解、静止画キャプチャだけで「検証完了」としない。
2. **実機・ブラウザ・自動入力による操作観測**:
   - 利用可能なツール（Browser Tools, Playwright, 実機起動）で開始→主操作→ミス/達成→リスタートの全遷移を実際に操作する。
   - 入力手順、期待する触感、実際の挙動、画面レスポンスを客観的に記録する。
   - 自動操作環境がない場合は、ロジックテストを固めた上で手動確認手順と未検証範囲を明記する。

### Phase 5: 手触り（Game Feel）とゲーム性の改善（Polishing）
1. **体験阻害要因の優先度順解決**:
   - ① 進行不能・入力不能（致命的欠陥）
   - ② ゼロ待機UI違反（画面遷移のもっさり、スキップ不能な演出）
   - ③ 手触りの硬さ（ヒットストップ欠如、等速直線運動、ジャンプの浮遊感）
   - ④ 駆け引きの破綻（ノーリスク・ハイリターンな待ち・安全策の放置）
   - ⑤ 理不尽感（予兆のない即死・見えない落とし穴）
2. **一度に少数の変数を変えて再測定**: 「観測 → 仮説 → 単一パラメータ/ロジック変更 → 同条件での再検証」の記録を残す。
- *詳細リファレンス*: [references/game-feel.md](references/game-feel.md), [references/gameplay.md](references/gameplay.md)

## 領域別コア原則クイックリファレンス

### 1. 操作感・手触り（Game Feel）の鉄則
| 項目 | 原則 | 実装指針 |
|---|---|---|
| **ヒットストップ** | 大事なところは止める | 命中時、双方のアニメーションを3〜10F停止。微小シェイク後、ノックバック・エフェクトを一気に解放。 |
| **重量感** | 予備動作と緩急 | Windup（タメ 10〜20F）を長くとり、Active（判定）は瞬時。命中時に重低音SE＋カメラシェイクを同期。 |
| **ジャンプ** | 物理法則の意図的歪曲 | 下降重力1.5〜2.0倍、ボタン離上での低ジャンプカット、コヨーテタイム（5〜8F）、ジャンプバッファ（5〜8F）。 |
| **崖際の振る舞い** | 理不尽な落下の排除 | 崖端ブレーキ判定（Edge Stop）、わずかに届かない場合の崖掴まり（Ledge Grab）、壁滑走摩擦。 |
| **カメラ** | 注視点を固着させない | デッドゾーン（遊び）を設け、`SmoothDamp`で滑らかに追従。進行方向前方（Look-Ahead Offset）を広く見せる。 |
| **UI応答性** | 遅さは罪・素早く切替 | 画面遷移・階層開閉は最長0.1〜0.15秒以内。演出中も決定キー連打で即時スキップ。ポーズは即時完全停止。 |
| **視認性** | スタイルより機能美 | テキスト背景に半透明黒帯または縁取りを敷く。重要数値（瀕死・時間切れ）は点滅・拡縮アニメで周辺視野に警告。 |
| **自由の保証** | 必ず飛ばせる・止められる | ダイアログの瞬間全文表示、カットシーンの常時スキップ、状態完全保持のポーズ。 |

### 2. ゲーム性・駆け引き（Gameplay）の鉄則
| 項目 | 原則 | 実装指針 |
|---|---|---|
| **リスク＆リターン** | 駆け引きの本質 | 安全地帯（ノーリスク/ノーリターン）と危険地帯を分離。リターン行動に隙・硬直・被弾判定露出をバインド。 |
| **緊張と緩和** | ギュッとしてパッと解消 | チャージ（無防備・移動制約）でストレスを溜め、解放時に広範囲・高威力で爽快感を返す。 |
| **敵の存在意義** | 動的プレッシャー | 敵は標的ではなく「安全地帯を破壊する存在」。定位置待ちや遠距離連射を崩すカウンター行動を持たせる。 |
| **3すくみ・相性** | 支配的戦略の解体 | 強力な万能コマンドを排除し、循環関係（A beats B, B beats C, C beats A）と排他的ステート判定を組む。 |
| **運と実力** | 入力の運・劣勢補正 | 結果の乱数（ダイス命中）を避け、配牌・出現の乱数（入力の運）にする。劣勢時のラバーバンディング。 |
| **予兆と反応** | 納得感のある猶予 | 強攻撃は `予兆(Windup ≥15F) -> 判定(Active) -> 後隙(Recovery)` に厳格分離。見てから回避できる時間を保証。 |
| **リトライの快適さ** | 失敗摩擦の極小化 | 死亡から再開まで数秒以内。難所の直前にチェックポイントを自動配置し、前座の往復を強要しない。 |
| **待ち戦術の打破** | 攻勢へのインセンティブ | ガードにシールド耐久値を設定。前進・攻撃継続へのバフ付与、引きこもりへのデバフ/資源枯渇。 |
| **体感確率** | 認知バイアス補正 | 擬似乱数（PRD: 連続失敗で確率上昇）を採用。90%以上は体感100%に近づけ、危険イベントは連続発生を防止。 |
| **遊びの核** | マイクロ・コアループ | 5〜15秒の「課題提示 → 操作実行 → 爽快な結果」が幾何学図形だけでも楽しい状態を最優先で確立する。 |

## 自律エージェントの行動ガードレール

1. **既存コードと環境の尊重**:
   - 既存のリポジトリやフレームワーク（Phaser, Unity, Godot, Canvas API, Three.js等）を優先し、スキル都合で勝手に別スタックへ作り直さない。
2. **勝手な引き算の禁止**:
   - ユーザーが明示的に指定した必須要件を、「引き算の原則」を口実にして無断で削除しない。
3. **客観的証拠の提示**:
   - 「面白さを証明した」「完璧な操作感になった」と主観で断定しない。変更したパラメータ（数値・単位）、測定したフレーム数、操作手順、観測された挙動を事実として報告する。
4. **安全と権限の遵守**:
   - 外部通信、破壊的ファイル削除、高負荷な無限ループの防止。
